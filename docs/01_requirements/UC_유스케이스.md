# 전자식 차일드락 제어 SW 유스케이스

| 항목 | 내용 |
|---|---|
| 문서 ID | UC-001 |
| 관련 문서 | SWRS-001 SW 요구사항 명세서 |
| 기준선 | BL-SWR-1.0 |

## 1. 액터

| 액터 | 설명 |
|---|---|
| 운전자 | 물리 버튼, AVN, 음성, 모바일 앱으로 잠금·해제 명령 (OEM-IF-004) |
| 차량 | 차속, 기어, 충돌, 접근위험, 화재, 과온, 성인 탑승, ISOFIX, 시동, 센서 고장 신호 제공 |
| 구동기 모델 | 도어별 LOCK/RELEASE 출력 수신 (PC/SIL 논리 출력) |
| 시험자 | Web 시뮬레이터로 입력 주입, 상태·이벤트 조회 |

## 3. 유스케이스 상세

### UC-01 운전자 잠금·해제
- **사전 조건**: 시동 ON, 정지(차속 < 3.0 km/h), 입력 유효, 강제 조건 없음
- **기본 흐름**: 1) 운전자가 `side`(left/right/all), `action`(lock/unlock)을 선택해 명령 2) SW가 명령을 검증 3) 선택 도어에 적용 4) 상태·이유 코드(`DRIVER_COMMAND`) 제공
- **대안 흐름**: 2a) 명령 형식 오류 → 명령 거절, `COMMAND_REJECTED` · 3a) 해당 도어에 상위 규칙 활성 → 상위 규칙 결과 유지 (UC-03, UC-07, UC-10)
- **사후 조건**: 선택 도어만 명령대로, 나머지 도어 불변

### UC-02 주행 시작 자동 잠금
- **사전 조건**: 시동 ON, 양쪽 RELEASE
- **기본 흐름**: 1) 차속이 3.0 km/h 이상이 됨 2) 반영 주기에 양쪽 LOCK, `AUTO_LOCK_SPEED`
- **대안 흐름**: 1a) 주행 중 운전자 unlock → 거절 (`AUTO_LOCK_SPEED` 유지) · 1b) 주행 중 화재·성인 탑승 → 강제 해제가 우선
- **사후 조건**: 정지 후에도 LOCK 유지

### UC-03 접근위험 해제 억제
- **사전 조건**: 시동 ON, 해당 도어 RELEASE 또는 LOCK
- **기본 흐름**: 1) 도어 d 접근위험 TRUE 2) 도어 d LOCK (`APPROACH_RISK_LOCK`) 3) 운전자가 도어 d unlock 4) 억제, `APPROACH_RISK_SUPPRESSED`, 억제 시각 t0 기록
- **대안 흐름**: 4a) 10.0 s 이내 재입력 → UC-04 · 1a) 반대쪽 도어는 영향 없음
- **사후 조건**: 접근위험이 끝나도 도어 d는 LOCK 유지 (활성 규칙 없음 → 직전 유지)

### UC-04 override
- **사전 조건**: UC-03 4단계 완료 (도어 d 억제 시각 t0)
- **기본 흐름**: 1) 정지(차속 < 3.0 km/h) 상태에서 t0 후 10.0 s 이내 도어 d 포함 unlock 재입력 2) 도어 d RELEASE, `state = OVERRIDE`, `DRIVER_OVERRIDE`
- **대안 흐름**: 1a) 10.0 s 초과 재입력 → 다시 억제, t0 갱신 · 1b) 도어 d ISOFIX TRUE → override 불가, LOCK 유지 · 1c) 차속 ≥ 3.0 km/h → override 불가, 억제
- **사후 조건**: 접근위험이 FALSE가 되거나 차속이 3.0 km/h 이상이 되면 OVERRIDE 종료, t0 초기화 (주행 시작 시 자동 잠금)

### UC-05 충돌 후 해제
- **사전 조건**: 시동 ON
- **기본 흐름**: 1) `crash_status = CONFIRMED` 2) 반영 주기에 양쪽 RELEASE, `CRASH_RELEASE` 3) 이후 모든 잠금 요인 무시 (충돌 래치)
- **대안 흐름**: 1a) `PENDING` → 출력 불변, `CRASH_PENDING` · 1b) 같은 스냅샷의 다른 그룹이 형식 오류여도 충돌 그룹이 유효하면 해제 · 2a) 센서 고장·입력 지연 중에도 해제 (상태는 FAULT/DEGRADED 표시)
- **사후 조건**: 시동 OFF까지 RELEASE 유지

### UC-06 강제 해제
- **기본 흐름**: 1) 화재, 과온, 성인 탑승 중 하나 TRUE 2) 반영 주기에 양쪽 RELEASE, 입력별 이유 코드
- **대안 흐름**: 1a) 성인 탑승 + ISOFIX → ISOFIX 도어는 LOCK 유지 · 1b) 화재 + ISOFIX → 양쪽 RELEASE · 1c) 화재·과온 + 센서 고장 → 양쪽 RELEASE (성인 탑승 + 센서 고장 → 출력 유지)

### UC-07 ISOFIX 잠금
- **기본 흐름**: 1) 도어 d ISOFIX TRUE 2) 반영 주기에 도어 d LOCK, 반대쪽 유지, `ISOFIX_LOCK`
- **대안 흐름**: 1a) 운전자 도어 d unlock → 거절

### UC-08 시동 OFF
- **기본 흐름**: 1) `ignition_on = FALSE` 2) 반영 주기에 양쪽 RELEASE, `state = OFF`, `IGNITION_OFF` 3) 충돌 래치·override 초기화

### UC-09 입력 이상·센서 고장
- **기본 흐름 (형식 오류)**: 1) 일부 입력 그룹이 범위·형식 위반 2) 그 그룹만 거절(직전 값 유지), 나머지 그룹은 평가, `input_validity = INVALID`
- **기본 흐름 (갱신 지연)**: 1) 어떤 그룹이 200 ms 초과 미갱신 (형식 오류 연속 수신 포함) 2) DEGRADED, 출력 유지, `INPUT_STALE` 3) 모든 그룹이 다시 신선해지면 복귀
- **기본 흐름 (센서 고장)**: 1) `sensor_fault = TRUE` 2) 출력 유지, FAULT, `W_SENSOR_FAULT` 3) FALSE 수신 시 복귀

### UC-10 우선순위 결정
- **기본 흐름**: 1) 여러 규칙 동시 활성 2) SWRS 3장 표에 따라 도어별 최상위 규칙 적용 3) `priority_reason`, `reason_code` 제공

### UC-11 상태·이벤트 조회
- **기본 흐름**: 1) 시험자가 Web에서 입력 주입 2) 상태 조회 3) 최근 이벤트 최대 100건 조회
- **대안 흐름**: 2a) 직렬화 실패 → HTTP 500 · 3a) 재기동 후 → 0건

### UC-12 결정론 재생
- **기본 흐름**: 1) 고정 시계와 입력 벡터 준비 2) 1,000회 재생 3) 출력 해시 비교 → 모두 동일
