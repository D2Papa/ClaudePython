## 1. 1차 검토 지적과 조치

| # | 심각도 | 지적 | 조치 |
|---|---|---|---|
| 1 | 높음 | 간섭 방지 논증 오류: ISOFIX(6)는 ASIL B 접근위험(7·8)보다 우선인데 재확인 대상에서 빠지고, `accept_qm`이 규칙-출력 짝을 검사하지 않아 결함 후보 `(ISOFIX, RELEASE)`가 접근위험 잠금을 풀 수 있음 | `types.RULE_OUTPUT` 고정 출력표, `accept_qm` 출력 일치 검사, ISOFIX 조건 재확인 추가. SWA 5장 논증 수정 |
| 2 | 높음 | 미수신(None) 값에서 `None >= 3.0` 등 `TypeError` → 판정 중단 | 모든 후보 함수에 None 분기 명시, 초기 상태 시험 추가 |
| 3 | 높음 | 지연·고장 동안 override 초기화 누락 → 고장 중 주행 후 복귀 시 override가 되살아남 | 지연·고장 주기에 override·t0 전체 초기화 (보수적 대안). SWRS 변경 CR-001, 가정 A-21 |
| 4 | 높음 | NaN/inf 타임스탬프 수락 → 영구 신선 판정 또는 이후 입력 고착 | `is_number`에 `math.isfinite`, 판정표·시험에 NaN/inf 추가 |
| 5 | 중간 | SWR-006 수용기준(`AUTO_LOCK_SPEED`)과 우선순위 표 결과(`APPROACH_RISK_LOCK`)가 모순 | SWRS 변경 CR-001로 수용기준 정정 |
| 6 | 중간 | SWA 인터페이스·시퀀스가 SWD와 불일치 (Context 생성 순서 등) | SWA 3.2·4.1·4.3을 SWD에 맞춤 |
| 7 | 중간 | 의존 규칙에 safety 내부 호출 누락, ASIL 상속 설명 불일치 | `safety.arbiter → crash, approach` 허용 명시, `qm.rules`를 QM으로 두는 근거 기재 |
| 8 | 낮음 | 타임스탬프 거절 시 명령 처리, 초기 결정 값 미정 | 명령도 폐기 명시, `INITIAL_DECISION` 정의 (CR-001) |
| 9 | 낮음 | 추적 불일치(SWR-020), 상태도 전이 누락, SAP에 Doxygen·커버리지 게이트 없음 | 정정, Ruff `D1` 도입(pyproject 반영), SAP 보완 |

## 2. 2차 재검증 지적과 조치

| # | 심각도 | 지적 | 조치 |
|---|---|---|---|
| A | 중간 | `qm_plausible`의 ISOFIX 재확인에 None 검사가 없어 결함 QM 후보 하나로 ASIL B 중재기가 예외로 중단 | `isofix is not None` 검사 추가, 결함 주입 시험에 미수신 사례 추가 |
| B | 낮음 | `accept_qm`과 `qm_plausible` 책임 중복 서술 | `accept_qm` 3)을 `qm_plausible` 호출로 정리 |
| C | 낮음 | `RULE_OUTPUT` 타입과 `DRIVER_COMMAND` 표현 불일치 | `DRIVER_COMMAND`를 표에서 제외, 예외 처리 명시. 이유 코드 미검증을 한계로 기록 |
| D | 낮음 | SWR-006-5 "다음 주기에는"이 중의적 | "다음 조건 중 하나가 성립하는 주기에(그 주기 안에서)"로 수정 |
| E | 낮음 | 컴포넌트 그림에 새 의존 화살표 누락 | 추가 |

재검증자는 A 수정 시 BL-SWA-1.0/BL-SWD-1.0 확정 가능으로 판정했다.

## 3. 요구사항 변경 (CR-001)

G2 검토에서 SWRS 결함이 발견되어 변경 요청 CR-001로 SWRS를 갱신했다 (SWRS 변경 이력 참고). 영향: SWR-006, SWRS 2.2. 추적표와 가정 A-21 갱신 완료.
