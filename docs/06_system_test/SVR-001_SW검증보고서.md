## 5. 검증하지 않은 범위

- HIL, 타깃 ECU, 실차, 도어 래치·구동기 물리 시험, 법규 시험 (OEM 사양 1.3 적용 경계에 따라 범위 밖)
- 실제 실행 시간·주기 지터: PC/SIL은 시계를 주입하므로 타이밍 요구(300/200/100 ms)는 **논리 주기 기준**으로만 검증했다 (가정 A-05: 주기 50 ms)
- 간섭 방지의 메모리·시간 보호: 단일 Python 프로세스의 한계 (SWA 5장)
- Web 화면 수동 확인 (STC-F-227~229)

## 6. 잔여 문제

1. **OEM 확인 필요 21건** (OEM-Q-001). 특히 Q-01~Q-07은 안전 판단에 영향. 답변이 작업 가정과 다르면 SWRS 변경과 재검증 필요.
2. **시험 명세의 요구사항 이슈 15건** (STS-001 "요구사항 이슈" 시트). 기대값을 확정하지 못해 일부 필드를 단정하지 않은 케이스가 있다. 주요 항목:
   - NO_CHANGE 도어의 `reason_left/right` 매핑 범위 (SWRS 3.2가 전체 `reason_code`만 정의)
   - 상위 규칙(순위 1~4) 활성 중 `W_SENSOR_FAULT` 경고 출력 여부
   - 차속 3.0 km/h가 되는 주기의 unlock을 새 억제로 기록하는지
   - override 유지 중 10 s 경과 후 unlock 처리, 상위 규칙 구간의 override 보존 여부
   - SWR-001 명령 조합을 전수(24) 대신 페어와이즈(16)로 시험
   → SWRS 개정 시 정의하고 해당 케이스의 단정 범위를 넓힌다.
3. 시험 명세의 시나리오 생성 스크립트는 저장소에 없다. `scenarios.json`은 직접 편집하거나, 케이스를 추가할 때 `sts_spec.json`과 함께 갱신한다.
