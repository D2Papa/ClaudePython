|---|---|

## 1. 범위

| 구분 | 포함 | 제외 |
|---|---|---|
| 기능 | 후석 좌·우 차일드락 잠금/해제 판단, 상태·이유 코드, 이벤트 기록 | 도어 래치·구동기 HW, CAN/LIN 드라이버 |

## 2. 기술 결정

| ID | 결정 | 근거 |
|---|---|---|
| D-01 | 코드는 Python 3.12 호환으로 작성하고, CI에서 3.12와 3.13 모두 시험한다. Ruff `target-version = "py312"` | OEM 사양 3장은 Python 3.12, CLAUDE.md는 3.13 이상 |
| D-02 | Web 시뮬레이터는 FastAPI + 정적 HTML | OEM-IF-006이 HTTP 오류 응답을 요구, 경량 |
| D-03 | 판정 엔진은 시계를 주입받는 순수 함수로 구현 | OEM-NFR-001 결정론, 시험 용이성 |
| D-04 | ASIL B 관련 로직(입력 검증, 충돌, 접근위험, 센서 고장, override)과 QM 로직을 모듈로 분리. 단일 Python 프로세스에서는 freedom from interference를 완전히 보장할 수 없음을 한계로 명시 | ISO 26262-6 부분 적용 |

## 5. OEM 확인 필요 사항과 작업 가정

OEM 답변 전까지 아래 가정으로 진행한다. 각 가정은 G1 요구사항 문서에 `가정` 표시와 함께 기록하고, 답변이 오면 영향 범위를 갱신한다.

| ID | 이슈 | 관련 요구 | 작업 가정 |
|---|---|---|---|
| A-01 | ISOFIX 강제 잠금과 화재·과온·성인 강제 해제가 동시 발생 | FR-005, FR-006 | 우선순위: 비상 해제(충돌 CONFIRMED·화재·과온) > 강제 잠금(접근위험·ISOFIX) > 성인 탑승 해제 > 운전자 명령·자동 잠금. 생명 위협 상황의 탈출을 최우선, 아동 보호 신호를 편의성 해제보다 우선 |
| A-02 | QM 기능 override(FR-003)가 ASIL B 접근위험 억제(SR-002)를 해제 | SR-002, FR-003 | override는 OEM 요구대로 허용하되, ASIL B 모듈 안에서 구현하고 ASIL B 수준으로 개발·시험한다 (QM 모듈이 ASIL B 출력을 바꾸지 않도록) |
| A-03 | 센서 고장(출력 유지)과 충돌 CONFIRMED(해제) 동시 발생 | SR-001, SR-004 | 충돌 CONFIRMED가 우선 — 충돌 후 탈출 경로 확보 |
| A-04 | 충돌 해제의 "다른 명령"에 강제 잠금 입력 포함 여부 | SR-001 | 포함 — 충돌 CONFIRMED는 접근위험·ISOFIX 강제 잠금보다 우선 |
| A-05 | 평가 주기 미정의 | SR-001, SR-003 외 | 평가 주기 50 ms (설정 가능). 100 ms DEGRADED 예산에 여유 확보 |
| A-06 | 충돌 PENDING 동작 미정의 | SR-001 (SWR-008) | 출력 변경 없음, PENDING 이유 코드만 기록 |
| A-07 | override의 "같은 해제 명령" 정의, 10초 기산점 | FR-003 | 같은 도어(`all`은 양쪽 포함)의 unlock이면 source 무관. 해당 도어의 첫 억제 시각부터 10.0초 이하(포함) |
| A-08 | 주행 중 강제 해제와 자동 잠금 충돌 | FR-002, FR-005 | A-01 우선순위에 따라 강제 해제 우선 |
| A-09 | `gear` 입력 용도 없음 | IF-001 | 형식·범위만 검증하고 판정에는 쓰지 않음 |
| A-10 | 추적표에 SWR-019 없음 | 9장 | 결번으로 처리, OEM에 누락 여부 확인 |

## 6. 품질 기준

CLAUDE.md의 소스 코드 품질 기준을 따른다: branch 커버리지 100%, 테스트 성공률 100%, 순환 복잡도 10 이하, 함수 순수 코드 50줄 이하, 주석률 20% 이상, Google Python 명명 규칙, Doxygen 주석. 함수 길이와 주석률은 `tools/check_quality.py`로 측정한다.

## 7. 형상·변경 관리

- GitHub Flow, 단계·기능 묶음마다 브랜치와 PR. `main` 직접 push 금지.
- 결함과 OEM 질의는 GitHub Issue로 관리하고 PR·커밋에 Issue 번호를 연결한다.
- OEM 입력 문서(`OEM/`)는 교육용 저작물로 외부 공개가 금지되어 있어 저장소에 커밋하지 않는다.
