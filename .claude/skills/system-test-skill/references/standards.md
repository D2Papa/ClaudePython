# 표준 요건과 산출물 대응

이 스킬의 산출물이 각 표준의 어떤 요구를 충족하는지 정리한다. 테스트 명세에 표준 조항을 인용할 필요는 없지만, 아래 요구를 빠뜨리지 않도록 설계 시 점검표로 쓴다.

## A-SPICE

시스템 수준이면 SYS.5 (System Qualification Test / v4.0: System Verification), SW 수준이면 SWE.6 (Software Qualification Test / v4.0: Software Verification)이 대상이다. 두 프로세스의 기본 실행(BP)은 구조가 같다.

| A-SPICE 요구 (v3.1 / v4.0) | 이 스킬에서의 대응 |
|---|---|
| 테스트 명세 작성 — 요구사항에 대해 테스트 케이스 개발 (v3.1 BP2 / v4.0 BP1 verification measures) | 기능/비기능 시트의 케이스 |
| 각 케이스의 판정 기준(pass/fail criteria) 명시 | `예상 출력값`을 관측 가능한 구체적 값으로 작성 |
| 테스트 기법 명시 | `사용한 테스트 기법` 열 |
| 사전 조건, 테스트 환경 | `사전 조건` 열, 비기능 케이스의 측정 방법 |
| 양방향 추적성 (v3.1 BP5 / v4.0 BP4) | `추적성 매트릭스` 시트 (베이시스 → 케이스, 케이스 → 베이시스) |
| 일관성 보장 (v3.1 BP6) | 검증 스크립트: 존재하지 않는 ID 참조, 미커버 요구사항, 중복 케이스 검출 |
| 회귀 테스트를 위한 케이스 선택 (v3.1 BP3 / v4.0 BP2) | 케이스 ID 체계와 기법 표기로 선택 근거 제공 |

## ISO 26262-6 (2018) 11절 — 임베디드 SW 테스트

- **테스트 케이스 도출 방법** (ASIL에 따라 권장 수준이 다름):
  - 요구사항 분석 — 모든 ASIL에서 강력 권장
  - 동치 클래스 생성·분석 — ASIL A 권장, B~D 강력 권장
  - 경계값 분석 — ASIL A 권장, B~D 강력 권장
  - 지식·경험 기반 오류 추측 — 권장 (이 스킬의 WoW 검증/제안 케이스가 해당)
- **테스트 방법**: 요구사항 기반 테스트, 결함 주입(fault injection) 테스트 등. 비기능 시트의 강건성·고장 처리 케이스가 결함 주입에 대응한다.
- **테스트 환경**: HIL, ECU 네트워크, 차량 등. 환경에 따라 실행 가능한 입력·관측 수단이 달라지므로, 사용자가 환경을 알려줬다면 절차와 관측 방법을 그 환경에 맞춘다.
- **요구사항 커버리지**: 안전 요구사항을 포함한 SW 요구사항이 테스트로 커버되어야 한다 → 커버리지 100% 검증.

ASIL 등급이 주어지면 `추적성 매트릭스`에 함께 표시해, 고 ASIL 요구사항에 BVA·ECP가 적용됐는지 한눈에 볼 수 있게 한다.
